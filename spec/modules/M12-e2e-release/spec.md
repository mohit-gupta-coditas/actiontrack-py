## 1. Purpose
Prove the whole tool meets the acceptance criteria (root spec §16) on the provided sample notes. Check the CLI performance budget.
Ship the README and CI that keep it that way.

## 2. Sample data
- The provided `notes/` folder (30+ files, some long and messy, some deliberately malformed) is committed under `notes/`. **It isn't in
  the repo yet, and the user needs to provide it.**
- `tests/e2e/expected.yaml` is written **by hand after reading the notes** (not generated by the tool):
  ```yaml
  skipped:            # file → reason
    notes/bad-yaml.md: invalid_frontmatter
  min_unique_items: 0           # filled in from manual review
  duplicates:                   # items known to repeat across notes
    - owner: priya.shah@coditas.com
      task_contains: revised quote
      min_sources: 3
  ambiguous:                    # lines with a shared first name
    - file: notes/x.md
      line: 14
  ```
- The e2e tests run the CLI as a **subprocess** (`sys.executable -m actiontrack`) against a temp DB with `ACTIONTRACK_TODAY` fixed.

## 4. Performance (REQ-CLI-08)
- `actiontrack --help`, `actiontrack list` (on the sample DB) and `actiontrack done <bad id>` each start in **< 300 ms** (median of 5
  subprocess runs after one warm-up, on CI's Linux runner). Marked `slow`.
- Ingest of the sample folder: < 5 s (an informational budget that fails at 2× to catch regressions).

## 5. Release items
- `README.md`: install (`pipx install .` / `uv tool install .`), configuration (with a Gmail MCP section), a quickstart, an example for each
  command, the exit code table, the "never sends" guarantee.
- `.github/workflows/ci.yml`: matrix Python 3.11/3.12/3.13 × ubuntu/windows. Steps: `uv sync`, ruff, mypy, `pytest -m "not slow"`
  then `pytest -m slow` (ubuntu only), and `scripts/trace_check.py`.
- `scripts/trace_check.py`: fails if any REQ ID in root §18 has no test case in `spec/modules/*/tests.md`, or is owned by more than one module.
- A clean-venv install smoke test: build the wheel, install it into a new venv, `actiontrack --version`.
- **Manual smoke test** (documented, not automated): with the real Gmail MCP server configured, `followup <me> ` creates a
  draft in your own Gmail. Confirm it shows up under Drafts and that nothing was sent.
