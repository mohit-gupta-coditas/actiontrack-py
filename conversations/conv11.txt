    - Pin mcp<2: Downgrade to mcp 1.x so the spec names work as written; no pagination handling.
    - 2.x, first page only: Use 2.x names but only check the first list_tools page.
  Q [Outbox slug]: G17 — write_outbox names files <owner-key-slug>-<YYYYMMDDTHHMMSS>.eml, but the slug rule is undefined. Owner keys look like 'priya.shah@coditas.com' or 'name:priya' (G1). What slug rule?
    - Safe-char slug (Recommended): Lowercase; every run of chars outside [a-z0-9._-] becomes '-', trimmed of '-'/'.'; empty → 'unknown'. e.g. priya.shah-coditas.com, name-priya. Timestamp = `now` in its own (local) timezone.
    - Local part only: Use the part before '@' (or after 'name:'), e.g. priya.shah, priya. Shorter but can collide across domains.
    - Hash: First 8 hex chars of sha1(owner_key). Safe but not human-readable.
  Q [Required args]: G18 — Schema validation checks the mapped arg names exist in input_schema.properties. What if the tool's schema marks other args as `required` that we don't map (e.g. a required `cc` or `from`)?
    - Fail before calling (Recommended): Also raise ExternalServiceError when input_schema.required lists names we don't send, naming them; no call is made. Clearer than a server-side validation error.
    - Only check mapped names: As written: ignore `required`; if the server rejects the call, surface its error.
  Q [Draft link]: G19 — The spec builds the link as https://mail.google.com/mail/#drafts?compose=<id>. A Gmail API draft ID (r-…) is usually not the compose ID, so that link may not open the draft. What should DraftResult.link be?
    - Server link, else built (Recommended): Use a `link`/`url` returned by the server (structured or text JSON) when present; otherwise fall back to the spec's built link when an ID was found.
    - Keep spec link: Always build #drafts?compose=<id> from the ID; ignore any server link.
    - Drafts folder: Link to https://mail.google.com/mail/#drafts whenever an ID was found.
